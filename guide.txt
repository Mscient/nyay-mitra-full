02  |  The Legal Document Engine — Complete Documents, Not Drafts
This is the most critical differentiation of Nyay-Mitra. When a user completes a document workflow, they receive a document that is legally complete, executed, stamped, signed, and admissible in court — without any 'DRAFT' label or need for a separate lawyer review step for standard documents. Here is exactly how this works.
2.1  Why 'Draft' Is Not Acceptable — The Full Service Model
Existing platforms like LegalDesk and Vakil No1 generate template-filled Word documents or PDFs labelled as drafts. The user still has to: (a) buy stamp paper separately, (b) print and sign physically, and (c) get it notarised or registered if needed. Nyay-Mitra eliminates all these steps inside one workflow.

2.2  What Makes a Document Legally Complete in India
Legal Validity Framework
Under Indian law, a document is legally complete when: (1) it is on appropriate stamp paper of correct value — Indian Stamp Act 1899, (2) it is signed by all parties — IT Act 2000 Section 5 accepts Aadhaar eSign, (3) it is witnessed where required, (4) it is registered at Sub-Registrar where required (property deeds, some leases). Nyay-Mitra handles 1, 2, and 3 fully in-platform. For registration (4), the platform guides users and generates the e-registration application.
Component 1 — Stamp Duty Engine
Every Indian state has different stamp duty rates for different document types. The engine implements all state-specific rules:
State × Document Type → Duty Rate lookup table (maintained in PostgreSQL, updated on gazette notifications)
Duty calculation: percentage of transaction value OR fixed amount, whichever applies per state law
SHCIL e-stamp API integration: platform pays SHCIL, receives e-stamp certificate with Unique Identification Number (UIN)
E-stamp is tied to the document: UIN + party names + purpose printed on stamp certificate, linked to document hash
Verification: anyone can verify the e-stamp via SHCIL portal using the UIN — tamper-proof
// Stamp Duty Engine — Core Logic (Node.js)
async function calculateStampDuty(docType, state, transactionValue) {
  const rule = await db.stampRules.findOne({ docType, state });
  if (rule.basis === 'PERCENTAGE') {
    return Math.ceil(transactionValue * rule.rate / 100);
  } else if (rule.basis === 'FIXED') {
    return rule.fixedAmount;
  } else if (rule.basis === 'SLAB') {
    return rule.slabs.find(s => transactionValue >= s.min && transactionValue < s.max).duty;
  }
}

async function procureEStamp(duty, docType, state, party1, party2) {
  const res = await shcilAPI.post('/estamp/procure', {
    duty_amount: duty, state_code: state, document_type: docType,
    first_party: party1, second_party: party2,
    purpose: DOCUMENT_PURPOSE_MAP[docType]
  });
  return { uin: res.data.uin, certificate_url: res.data.cert_url, txn_id: res.data.txn_id };
}
Component 2 — Aadhaar eSign Integration
Aadhaar eSign under IT Act 2000 Section 3A is legally equivalent to a wet (ink) signature. It is the most accessible digital signing method in India — requires only an Aadhaar-linked mobile number.
Provider: Signzy or Digio (both NSDL-licensed ASPs — Application Service Providers) — REST API
Flow: Nyay-Mitra sends document hash (not full document) to eSign API → signer receives OTP on Aadhaar-linked mobile → OTP entered → DSC (Digital Signature Certificate) issued by NSDL → signature embedded in PDF
The document itself never leaves Nyay-Mitra servers — only the SHA-256 hash is sent to the eSign provider
Every signature produces: cryptographic signature, timestamp, signer's Aadhaar-verified identity, audit trail from UIDAI
Admissible in court under Indian Evidence Act 1872, Section 65B
// eSign Flow — docgen-svc (Node.js)
async function initiateESign(documentId, signerAadhaar, signerMobile) {
  const doc = await vault.getDocument(documentId);
  const hash = crypto.createHash('sha256').update(doc.buffer).digest('hex');

  const session = await signzyAPI.post('/esign/initiate', {
    document_hash: hash,
    document_id: documentId,
    signer_aadhaar: signerAadhaar, // Only last 4 digits stored post-signing
    signer_mobile: signerMobile,
    signing_reason: 'Agreement execution',
    callback_url: `${BASE_URL}/webhooks/esign/${documentId}`
  });

  return session.data.signing_url; // Redirect user to this URL for OTP entry
}

async function onESignComplete(documentId, signatureData) {
  // Embed cryptographic signature into PDF
  const signedPdf = await pdfEngine.embedSignature(documentId, {
    signature_bytes: signatureData.pkcs7_signature,
    certificate: signatureData.dsc_certificate,
    timestamp: signatureData.signed_at,
    signer_name: signatureData.verified_name // From Aadhaar eKYC
  });
  await vault.storeDocument(documentId, signedPdf, { status: 'EXECUTED' });
}
Component 3 — PDF Assembly Engine
The final PDF is assembled as a legally structured document — not a plain PDF. It includes:
Page 1: E-stamp certificate (SHCIL-issued, with UIN and QR code for verification)
Pages 2–N: The document body, formatted per document type conventions
Signature page: Each party's Aadhaar eSign with timestamp, name, and DSC reference
Audit trail page: Complete event log — who initiated, who signed, when, from which IP, OTP verified
Embedded metadata: Document hash, UIN, all signer certificate hashes — invisible but verifiable
QR code on every page linking to Nyay-Mitra verification portal — anyone can verify authenticity
Registration-Required Documents
Property sale deeds, long-term leases (>11 months in most states), and gift deeds require registration at Sub-Registrar office under Registration Act 1908 — this cannot be done digitally yet. For these documents, Nyay-Mitra generates a complete stamped and signed document AND books the Sub-Registrar appointment. The user still visits once — but with a complete, correct document. All other documents (agreements, affidavits, NDAs, employment contracts, etc.) are complete without registration.

2.5  Affidavit Notarisation — Completing the Loop
Affidavits require a Notary's seal — which cannot be done digitally under current Indian law. Nyay-Mitra's solution:
Platform generates the affidavit on correct judicial stamp paper value
Aadhaar eSign applied by deponent before printing
Platform shows nearest empanelled Notary from the Nyay-Mitra Notary Network
Notary can also be on-platform — book 15-min video call appointment, Notary applies their DSC-based seal
States where video-notarisation is accepted: Maharashtra, Delhi, Karnataka (growing list)
Legal Standing of Video Notarisation
The Registration (Amendment) Act 2025 and individual state amendments are progressively enabling video-based document registration and notarisation. Nyay-Mitra will track state-by-state status and auto-enable video notarisation as states adopt it. Currently: Maharashtra and Delhi permit it for some document categories.
03  |  Database Design — Schema, Courts, Cases, Lawyers
Every table in Nyay-Mitra's database is designed with three constraints in mind: multi-tenancy (row-level security per tenant), audit trail (every write is logged), and DPDP compliance (personal data fields are encrypted at column level).
3.1  Core Schema — Identity & Users
-- Users table (all user types)
CREATE TABLE users (
  id            UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  tenant_id     UUID NOT NULL REFERENCES tenants(id), -- org/firm for B2B; self for B2C
  email         TEXT UNIQUE NOT NULL,
  phone_enc     BYTEA, -- AES-256-GCM encrypted
  full_name_enc BYTEA, -- AES-256-GCM encrypted
  user_type     ENUM('CITIZEN','ADVOCATE','STUDENT','ORG_ADMIN','PLATFORM_ADMIN'),

  aadhaar_ref   TEXT, -- Only last 4 digits stored; not full number

  bci_verified  BOOLEAN DEFAULT FALSE,
  bci_state     TEXT, -- State Bar Council
  is_active     BOOLEAN DEFAULT TRUE,
  created_at    TIMESTAMPTZ DEFAULT NOW(),

8.2  Integration Architecture — Resilience Patterns
Circuit breaker: every third-party API call wrapped in Opossum circuit breaker — if SHCIL API is down, queue stamp procurement and retry
Fallback: eSign has two providers (Signzy primary, Digio fallback) — auto-switch on failure
Idempotency: all document generation jobs have idempotency keys — safe to retry without double-charging
Webhook verification: all incoming webhooks (eSign completion, payment) verified with HMAC signature
Timeout budgets: SHCIL 10s, eSign 30s (user waiting for OTP), IndianKanoon 5s, Razorpay 15s
Async everything: stamp procurement and eSign are async — user waits via polling or SSE push, not blocking HTTP
8.3  Data Pipeline — Court Data Ingestion
// Court data ingestion pipeline — Kafka consumer
consumer.subscribe(['court.raw.ecourts', 'court.raw.indiankanoon']);

async function processCourtRecord(record) {
  const { source, court_code, case_data } = record;

  // 1. Validate schema
  const valid = validateCaseSchema(case_data);
  if (!valid) { await quarantine(record); return; }

  // 2. Deduplicate
  const existing = await db.cases.findOne({ court_code, case_number: case_data.case_number, year: case_data.year });
  if (existing) { await updateCase(existing.id, case_data); return; }

  // 3. Extract entities (NER)
  const entities = await nlpService.extractEntities(case_data.full_text);
  // entities: { acts: ['IPC s.302','CrPC s.154'], judges: ['Hon. D.Y. Chandrachud'], ... }

  // 4. Encrypt PII (party names)
  const petitioner_enc = await vault.encrypt(case_data.petitioner);
  const respondent_enc = await vault.encrypt(case_data.respondent);

  // 5. Insert to PostgreSQL
  const newCase = await db.cases.insert({ ...case_data, petitioner_enc, respondent_enc, acts_involved: entities.acts });

  // 6. Index in Elasticsearch
  await es.index({ index: 'cases', id: newCase.id, body: {
    court_code, case_number: case_data.case_number, year: case_data.year,
    subject: case_data.subject, acts: entities.acts, status: case_data.status,
    full_text: case_data.full_text, // For full-text search
    embedding: await nlp.embed(case_data.full_text?.substring(0, 1000)) // For semantic search
  }});
}
