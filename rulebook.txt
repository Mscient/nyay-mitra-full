02  |  The 25 Non-Negotiable Rules — Printed, Pinned, Permanent
These 25 rules are absolute. They apply to every engineer, every PR, every deployment, every AI prompt, and every AI feature. If a rule blocks your work, escalate — do not work around it.
PART A — Rules for Using AI to Build Nyay-Mitra
R01
Never Paste Real User Data Into Any AI Tool
Never send actual client names, case numbers, Aadhaar numbers, phone numbers, or any production data into Claude, Copilot, ChatGPT, Cursor, or any external AI tool during development. Use only synthetic data. Real data in external AI = immediate DPDP violation.
R02
Every AI-Generated Code Block Gets a Human Security Review
AI code assistants produce vulnerable code in up to 62% of cases (2025 research). Every function generated by AI must be reviewed by a human developer before merge. No auto-merge of AI code ever. The reviewer signs off — not the AI.
R03
Verify Every AI-Suggested Package Before Installing
LLMs hallucinate package names that do not exist — attackers publish malicious packages with those names. Before npm install or pip install of any AI-suggested package: verify it on npmjs.com/pypi.org, check download count, check last publish date, check maintainer. Zero exceptions.
R04
Never Hardcode Any Secret — AI Code or Human Code
GitHub reported 39 million leaked secrets in 2024. AI code assistants are trained to follow patterns and may reproduce API keys from training data. All secrets in HashiCorp Vault. Run git-secrets and trufflehog on every commit. If a secret is ever committed: rotate it within 10 minutes.
R05
Maintain an AI Bill of Materials (AIBOM) for Every Feature
CERT-In's 2025 AI advisory requires an AI Bill of Materials. For every AI feature in Nyay-Mitra, document: which model is used, version, provider, what data it receives, what it outputs, and any known limitations. Update the AIBOM when models change. This is a legal requirement.
R06
Test AI Features for Bias Before Shipping
MeitY's March 2024 advisory requires platforms to test AI models for bias. Before any AI feature ships: test outputs across all 28 states, all major languages, across gender and income proxies. Document results. If bias detected: do not ship. Fix first.
R07
All AI-Generated Code Must Pass the Same CI/CD Security Gates as Human Code
SAST (SonarQube), dependency scan (Snyk), secret scan (trufflehog), and DAST (OWASP ZAP) apply equally to AI-generated and human-written code. AI is not exempt from quality gates. There is no 'AI fast lane' to production.
R08
Document What AI Was Used For in Every PR Description
Every pull request must state: which AI tools were used, which parts of the code were AI-generated, and what human review was performed on those parts. This creates an audit trail and a training feedback loop for the team.
PART B — Rules for AI Features Inside Nyay-Mitra (What the Product Does)
R09
AI Is An Assistant — Never a Decision Maker
Nyay-Mitra AI suggests, drafts, summarises, and retrieves. It never decides: who wins a case, whether to file, what legal strategy to take, whether someone is guilty. Every AI output is an input to a human decision. Encode this in every AI feature's UX copy.
R10
Every AI Output Visible to Users Must Be Labelled
MeitY March 2024 advisory: unreliable AI outputs must be labelled. For Nyay-Mitra: every AI-generated document draft, every case summary, every legal explanation must show 'Generated by AI — Verify before relying.' No exceptions. This label cannot be hidden, dismissed, or minimised.
R11
No Client PII in External AI API Calls Without Explicit Consent
Before any user data (name, case number, phone, matter description) goes into an API call to Claude, OpenAI, or any external AI: (a) the user must have explicitly consented to AI processing, (b) PII must be pseudonymised where possible, (c) a DPA must be signed with the AI provider.
R12
No Outcome Prediction Shown to Citizens
Nyay-Mitra will never show a citizen 'You have a 72% chance of winning.' This is legal advice under the Advocates Act and creates false expectations. Instead: show pattern data — 'In 847 similar cases at Bombay HC, courts ruled for tenants in 72% on this issue.' Factual, not predictive.
R13
AI-Generated Legal Documents Are Always Reviewed Before Execution
Every AI-generated document goes through the following gate before stamp + sign: (a) advocate-users confirm professional review, (b) citizen-users get a mandatory 'Have a lawyer review this' prompt with a 30-min booking offer. The execute button is only active after this step.
R14
Self-Hosted AI Mode Must Be Available for Privileged Communications
Attorney-client privileged conversations that are processed by AI must never leave Nyay-Mitra infrastructure. Lawyers can select 'Air-gap mode' — processing only via self-hosted Llama 3 on our GPU cluster. No external API. This is a product feature, not a setting.
R15
AI Prompts Are Code — Version Control Them
Every system prompt, every template prompt, every few-shot example used in Nyay-Mitra's AI features must be in the Git repository under /prompts/. They are reviewed in PRs just like code. Changes to prompts require the same approvals as code changes. No ad-hoc prompts in production.
R16
Rate Limit All AI Endpoints — Hard Caps
AI API calls cost money and can be abused. Hard limits: 20 AI requests per user per minute; 10 document generations per account per hour on free plan; 100 per hour on paid. Implement at API Gateway level — not at application level. Failure to do this has bankrupted startups.
R17
Log Every AI Interaction — Immutably
Every AI call must log: user_id (hashed), timestamp, model + version, prompt hash (not full prompt), output hash, latency, cost, success/failure. Logs stored in S3 with Object Lock (WORM). Retention: 7 years. These logs are needed for legal discovery, CERT-In incidents, and bias audits.
R18
Hallucination Is a Bug — Treat It as One
When AI generates a case citation that does not exist, a stamp duty amount that is wrong, or a clause that misrepresents the law — that is a bug. It goes in the bug tracker with P1 severity. The feature is pulled until the hallucination is reproduced, root-caused, and fixed with a guardrail.
PART C — Security, Legal & Team Rules
R19
Advocates Act Boundary — Engrave This
Nyay-Mitra provides LEGAL INFORMATION not LEGAL ADVICE. The boundary: information explains the law generally; advice applies the law to a specific person's facts. Every AI feature that could cross this line must be reviewed by an empanelled advocate before shipping. Non-compliance: BCI shut-down order.
R20
MeitY Advisory Compliance Is Continuous — Not One-Time
MeitY's AI advisory requires platforms to continuously test AI models. Assign one engineer per quarter as AI Compliance Owner. They run the bias test suite, update the AIBOM, review the AI label implementation, and sign off. This is a quarterly deliverable, not a checkbox.
R21
No AI Feature Ships Without a User-Facing Explanation of What It Does
Every AI feature visible to users must have: (a) a plain-language explanation of what the AI does with their data, (b) an opt-out option where feasible, (c) a disclosure that AI is used. This is required by DPDP Act 2023 consent requirements and MeitY's guidelines.
R22
OWASP LLM Top 10 Is Checked for Every AI Feature
Before any AI feature goes live, the engineer responsible runs through the OWASP LLM Top 10 checklist (see Chapter 06 of this document). The completed checklist is attached to the feature's release PR. No AI feature ships without it.
R23
AI Models Must Be Pinned to Versions — No Auto-Upgrade
An AI model update can change output behaviour silently. Pin every AI model to a specific version (e.g., claude-sonnet-4-20250514, not 'latest'). Test before upgrading. Document what changed in behaviour after upgrade. Treat model upgrades like library upgrades: deliberate and tested.
R24
Keep Humans in the Loop for Any Irreversible Action
Any action that is irreversible — sending a legal notice, executing a document, making a payment, deleting a file — must have a human confirmation step that cannot be automated or bypassed by AI. No AI agent can trigger irreversible actions autonomously on this platform.
R25
The Privacy-by-Design Rule: AI Should Only See What It Needs
Before any AI call: strip the prompt to the minimum data needed for the task. If generating a clause suggestion, the AI does not need the client's name. If summarising an order, the AI does not need the billing information. Minimum data = minimum breach surface. Always.

4.2  The Nyay-Mitra Cursor / Claude Rules File
Every developer must have this file at .cursor/rules and .claude/instructions in the project root. It embeds security requirements directly into the AI assistant:
# NYAY-MITRA AI ASSISTANT RULES — v1.0
# All AI coding tools on this project must follow these rules.
 
## Security Requirements (Non-Negotiable)
- ALWAYS use parameterised queries. NEVER concatenate user input into SQL.
- ALWAYS validate and sanitise all user inputs before they reach any AI model.
- NEVER hardcode API keys, passwords, JWTs, or secrets of any kind.
- ALWAYS use AES-256-GCM for encryption of PII fields. Never MD5 or SHA1 for secrets.
- ALWAYS use bcrypt (cost 12) or Argon2id for password hashing.
- ALWAYS add rate limiting to any new endpoint. Default: 100 req/min per IP.
- For any new table: add row-level security policy isolating by tenant_id.
- NEVER expose internal error details in API responses. Log internally, return generic message.
 
## AI-Specific Rules
- Any function that calls an external AI API must: strip PII before the call, log the call hash, handle timeout < 10s.
- AI-generated document content must always pass through the guardrail checker before returning to user.
- NEVER allow AI model calls to trigger irreversible actions (payments, sends, deletes) without human confirmation.
- All AI prompts must be loaded from /prompts/ directory. No inline prompt strings in business logic.
 
## India Legal Platform Rules
- Documents returned to users must include the IS_AI_GENERATED flag in response metadata.
- All stamp duty calculations must be validated against the stamp_duty_rules table — never hardcoded.
- Legal text output must never include the phrases 'you will win', 'you have a strong case', 'I advise you to'.
- Aadhaar numbers must never be stored in full. Mask after KYC. Only last 4 digits in DB.
 
## Code Quality Gates
- All new code must have unit tests with > 80% coverage before PR.
- Security-sensitive functions (auth, crypto, file access) require a separate security reviewer.
- AI-generated code blocks must be tagged with // AI-GENERATED: [tool] in the first comment line.

7.1  The AI Consent Flow
On first use of any AI feature: user sees plain-language explanation of what AI does with their data
Consent is granular: user can consent to document AI without consenting to research AI
Consent is recorded in consents table with: user_id, feature, timestamp, IP, consent_text_version
Withdrawing consent: user can withdraw at any time from settings; AI processing stops within 24 hours
DPDP Rules 2025 requirement: consent must be as easy to withdraw as to give — same number of clicks
7.2  Right to Deletion — AI-Specific Obligations
When a user requests data deletion (DPDP right): all AI logs containing their data must be deleted within 72 hours
Embeddings generated from their documents must be deleted from the vector index
If their data was used in any fine-tuning: flag for model retraining with data removed (GDPR/DPDP 'machine unlearning')
Deletion verified with a signed audit certificate sent to the user's registered email
